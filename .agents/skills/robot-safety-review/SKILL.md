# 机器人安全审查

## 目的

用于审查 zl_robot 改动是否削弱运动安全、硬件安全、故障处理或实时控制假设。

## 安全关键范围

如果改动影响以下内容，按安全关键改动处理：

- 状态切换、故障检测、故障复位或系统状态权威。
- 命令路由、来源授权、优先级、序列检查或控制源边界。
- 控制过滤、限幅、NaN/Inf 拒绝、阻尼、准备插补或拒绝命令行为。
- 急停、阻尼、超时、失联保护、故障降级或恢复行为。
- 关节名称、顺序、单位、限位、硬件映射、踝关节转换或坐标空间。
- RL 模型输入、观测历史、动作缩放、输出解码、模型切换或推理状态。
- driver 写入门、故障锁存、维护服务、EtherCAT/CAN 行为或工作线程。
- timer、控制频率、callback group、executor、锁、队列、动态分配或高频日志。

## 审查流程

1. 识别被修改的安全关键路径和直接下游影响。
2. 判断行为前，先阅读相关包 README 和系统设计文档。
3. 检查现有安全机制是否被保留或增强。
4. 查找隐性行为变化：
   - 新增绕过路径。
   - 默认值变化。
   - 命令准入变宽。
   - 校验变弱。
   - 控制循环中新增阻塞操作。
   - 高频路径新增大量日志或动态分配。
5. 检查测试是否覆盖正常、边界和故障场景。
6. 如果真实硬件行为可能变化，标记需要实机验证；未经用户明确授权，不运行会驱动硬件的命令。

## 最小安全问题清单

相关时需要回答：

- 不安全命令是否更容易到达硬件？
- FAULT、DAMP、PREPARE、超时或复位行为是否改变？
- 关节限位、单位、映射或模型输入输出语义是否漂移？
- 时序、抖动、阻塞或并发行为是否可能变差？
- 诊断是否可能隐藏或延迟故障？
- 如果行为错误，是否有清晰回滚路径？

## 输出格式

按严重程度报告：

- Critical：可能导致不安全运动、硬件损坏或故障保护失效。
- High：改变安全边界、状态权威、命令准入或时序假设。
- Medium：测试缺失、行为不清晰或验证不完整。
- Low：文档、可观测性或可维护性问题。

每个问题包含：

- 文件/位置。
- 触发条件。
- 影响。
- 建议修复或验证方式。
