# 安全重构

## 目的

用于 zl_robot 中保持行为不变的代码重构。重构不得悄悄改变对外接口、运行行为、安全边界、控制时序或硬件控制语义。

## 风险分级

如果改动涉及以下内容，默认按高风险处理：

- ROS 接口、launch、参数、QoS、namespace 或 remap 行为。
- 状态切换、命令路由、控制过滤、安全检查或故障处理。
- 关节名称、顺序、单位、限位、硬件映射、踝关节转换或 RL 模型输入输出。
- 控制频率、timer、线程、锁、callback group、executor、队列或超时。
- driver 行为、硬件写入、维护服务或真实设备启停。

## 必经流程

1. 明确目标文件和重构原因。
2. 阅读目标包 `README.md`、构建文件、相关 launch/YAML 配置和直接调用方。
3. 修改前列出行为不变量：
   - ROS 接口和参数。
   - 状态、控制和安全行为。
   - 时序和并发假设。
   - 相关关节、RL 或模型语义。
4. 检查已有测试，并识别缺少现状覆盖的行为。
5. 高风险改动应先输出简短计划并暂停，除非用户已明确要求直接实现。
6. 小步修改，只处理本次重构目标；不要混入功能变更、性能优化或接口升级。
7. 修改后审查 diff，确认没有意外行为变化。
8. 执行最小但有效的构建和测试；无法进行硬件或启动验证时明确说明未验证范围。

## 验证优先级

优先提供以下证据：

- 被修改逻辑的单元测试或现状测试。
- `colcon build --packages-select <package>`。
- `colcon test --packages-select <package>`。
- ROS 接口兼容性审查。
- 控制链路相关改动的 launch、仿真、dry-run 或回放验证。

未实际执行的检查不得描述为已通过。

## 交付要求

最终说明：

- 重构目标和修改文件。
- 行为和接口兼容性判断。
- 实际执行的测试/命令和结果。
- 未验证的硬件、时序或集成风险。
- 建议回滚方式。
