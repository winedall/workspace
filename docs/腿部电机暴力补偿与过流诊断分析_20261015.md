# 腿部电机暴力补偿与过流诊断分析

> 分析对象：`z01_pa_walk` RL 行走策略在天工（tienkung）双足平台上的实测日志
> 分析时间：2026-10-14 ~ 2026-10-15
> 分析方法：基于 `recorder/` 下 `joint_commands.csv` / `joint_states.csv`（200Hz）的离线数值分析
> 结论状态：多数结论已由多日志交叉验证；「重心持续偏左」一项存在**数据矛盾，待验证**（见 §5）

---

## 1. 背景与目标

机器人在行走 / 原地转圈时出现「暴力补偿 + 抖动」：关节力矩瞬间爆发（峰值 200Nm 以上）、顿挫，最终在最新日志中触发**左膝电机过流保护停机**。本次分析目标：

1. 定位暴力补偿 / 抖动的**真正根因**；
2. 解释**为什么偏偏是左膝**反复出事；
3. 判断右髋 roll 执行异常是**机械限位 / 标定 / 电机**中的哪一类；
4. 排查左右腿是否存在**配置不对称**；
5. 追查**重心为何偏向左腿**。

## 3. 分析方法论（可复用）

### 3.1 命令帧与状态帧时间对齐
两路 CSV 时间戳不同步，用最近邻匹配（`searchsorted`），并只保留时间差 ≤15ms、且命令类型为 RUN(4) 的帧：

```python
idx = np.clip(np.searchsorted(cs, st), 1, len(cs)-1)
tl = np.abs(cs[idx-1]-st) <= np.abs(cs[idx]-st)
match = np.where(tl, idx-1, idx)
run = (np.abs(cs[match]-st) <= 15) & (ct[match] == 4)
```

### 3.2 实际生效 kp/kd 反算（最小二乘）
电机控制律 `tau = b0 + kp·(q_cmd − q_act) − kd·dq`，构造设计矩阵回归，验证配置里的增益是否真生效：

```python
e = q_cmd - q_act
A = np.column_stack([np.ones(len(e)), e, -vel])
sol, *_ = np.linalg.lstsq(A, tau, rcond=None)   # sol[1]=kp_hat, sol[2]=kd_hat
```
> 注意：`corr(e, vel)` 过高（>0.6）时存在多重共线性，`kd_hat` 不可靠；本数据 `corr(e,vel)≈0.51`，`R²≈0.91`，可用。

### 3.3 抖动量化指标
- `|tau|max`、`tau>80Nm` 帧数（对比 `max_effort=80Nm`）、`|e|max`；
- **高频力矩残差** `tau_hf_rms`：Butterworth 20Hz 低通后取残差 RMS，衡量高频抖动；
- **力矩突变率** `|dτ/dt|`：`np.abs(np.diff(tau))*fs`；
- `corr(tau, vel)`：判断阻尼是否起作用（≈0 说明阻尼未与速度对齐）。

```python
from scipy.signal import butter, filtfilt
b, a = butter(4, 20.0/(fs/2), 'low')
hf = tau - filtfilt(b, a, tau)          # 高频残差
tau_hf_rms = np.sqrt(np.mean(hf**2))
```

### 3.4 左右对称性分析
分**静态（PREPARE）**与**动态（RUN）**两段分别对比左右同名关节：
- 静态：`q_act − q_cmd` 偏置（判标定）、`|tau|`（判静摩擦/承重）；
- 动态：`|tau|mean`（承重）、`|e|`（跟踪）、命令单帧跳变（尖峰）。

### 3.5 延迟假设检验
- **传输延迟**：用状态帧的 `last_command_sequence` 反查命令帧 `msg_stamp`，得命令→状态延迟；
- **响应滞后**：`q_cmd` 与 `q_act` 互相关，找使相关系数最大的滞后帧数（200Hz，1 帧=5ms）。

### 3.6 命令尖峰检测（关键方法）
对每个关节的命令序列求一阶差分，对比 `mean` 与 `max`：正常平滑则 mean 极小，若 max 很大说明存在偶发暴力跳变。

```python
d = np.abs(np.diff(q_cmd[run]))
# d.mean() ~0.001 但 d.max() ~0.9rad/帧 => 命令毛刺
```

### 3.7 IMU 姿态分析
`imu_euler_roll/pitch/yaw` 单位为**度**（由 yaw 范围 ±180 确认）。用**中位数**而非均值抗毛刺；判断机身是否持续倾斜。

### 3.8 电机故障排查
```bash
grep -iE "motor_error|over-current|fault" zl_robot.log
cat recorder/events.csv
```

## 4. 关键分析结论

### 4.1 暴力补偿的真因：RL 命令端瞬时尖峰（非硬件跟不上）

**核心发现**：暴力力矩不是关节跟不上命令，而是 **RL 下发的位置命令本身偶发暴力跳变**，被高 `kp=150` 放大成力矩尖峰。

各腿关节命令单帧跳变（091629，RUN 段）：

| 关节 | cmd跳mean | cmd跳max | >0.3rad跳帧 |
|---|---:|---:|---:|
| **R_hip_r** | 0.0009 | **0.927** | **49** |
| R_ank_r | 0.0012 | 0.781 | 30 |
| R_hip_p | 0.0007 | 0.565 | 23 |
| L_hip_p | 0.0008 | 0.526 | 25 |
| R_knee | 0.0011 | 0.508 | 8 |
| R_ank_p | 0.0011 | 0.487 | 22 |
| L_knee | 0.0010 | 0.452 | 12 |

- 命令平时极平滑（单帧跳 mean 0.0006~0.0012rad），但**每个关节都有 0.3~0.9rad 的偶发暴力跳变**；
- 0.927rad/5ms 的跳变在物理上不可能是正常轨迹 → 判定为 RL 指令毛刺；
- 右髋 roll 最严重：`q_cmd` 曾在 100ms 内 −1.18↔+0.22 疯跳，而 `q_act` 平滑跟随（是命令乱跳，不是关节跟不上）。

> 来源推测：`policy` 偶发饱和输出，或 50Hz policy → 200Hz 下发插值不连续。

### 4.2 抖动排名（091629，按高频力矩残差）

| 排名 | 关节 | tau_hf_rms | \|dτ/dt\|max | \|tau\|max |
|---:|---|---:|---:|---:|
| 1 | R_hip_r（右髋roll） | 1.929 | 42420 | **224.8** |
| 2 | **L_knee（左膝）** | 1.251 | 33117 | 203.7 |
| 3 | L_hip_r（左髋roll） | 1.075 | 26194 | 204.4 |
| 4 | R_knee | 0.735 | 11585 | 81.1 |

肇事关节在不同日志间**游走**（踝→膝→膝+髋roll），非固定某一关节，印证根因是全局性的命令尖峰而非单关节硬件。

### 4.3 左膝过流停机（145013，确认的严重后果）

| 项目 | 内容 |
|---|---|
| 异常关节 | left_knee（motor_id=44, slave_id=3, bus=0, slot=3） |
| 错误码 | **motor_error=32 = 电机过流（over-current）** |
| 触发时刻 | 运行 t=255s（总录制仅 271s） |
| 告警 | 每秒重复共 17 次，16s 内从未清除 |
| 后果 | 左膝力矩归零、电机禁用变 limp、机器人停机 |
| 其他关节 | 全部正常，无任何错误码 |

过流成因：
- 过流前左膝力矩峰 **166.5Nm**，超过 `max_effort=80Nm` **达 2 倍**；
- `q_act` 被驱到 **2.64rad（151°）** 极限位、`|e|` 高达 2.87rad；
- 力矩长期超限 → 电流冲高 → 过流保护动作。

### 4.4 「为什么偏偏左膝」：排除延迟与静态标定

- **非延迟**：左膝 `q_cmd→q_act` 响应滞后 **55ms**，反比右膝（60ms）更小；命令→状态传输延迟全局 mean 2.72ms / p95 5ms / max 23ms，非单关节问题；
- **非静态标定**：PREPARE 静态段左右膝**完全对称**（q_act 0.352/0.345、偏置都 −0.005、|tau| 都 1.40）；
- **动态才不对称**：RUN 段左膝 `|tau|mean=11.66` vs 右膝 `2.25`（约 5 倍），左膝 `|e|mean=0.081` vs 右膝 `0.021`；
- 左膝 `tau>60Nm` 帧中 **54% 发生在 `|vel|<2rad/s`**（低速顶住大载荷，而非高速振荡）。

> ⚠️ 「左腿承重 5 倍」这一动态不对称的**稳健性存疑**，见 §5。

### 4.5 右髋 roll 异常：命令尖峰，非机械/标定/电机

| 嫌疑 | 证据 | 结论 |
|---|---|---|
| 标定偏 | PREPARE 静态左右髋 roll 偏置都 ≈0.002（多日志一致） | ❌ 排除 |
| 电机弱/坏 | 力矩能到 224Nm，`corr(|tau|,|e|)=0.89~0.93`，电机拼命出力 | ❌ 排除 |
| 机械限位 | `q_act` 平滑、深负命令仅占 0.07%、最长段 80ms（瞬时非持续顶墙）；左髋 roll 也 floor 在 −0.11（对称） | ❌ 排除 |
| **命令尖峰** | `q_cmd` 单帧跳 max=0.927rad，全关节最多 | ✅ **真因** |

### 4.6 配置对称性：左右腿完全镜像，无异常不对称

| 配置文件 | 对比结果 |
|---|---|
| `hw_tienkung.yaml` | direction 镜像（hip_pitch/knee 左右相反、roll/yaw/ankle 相同）；offset 镜像（hip_roll +30/−30、knee +5/−5）；kt 对称（髋膝 3.5、踝 1.6）；motor_id 41–46 / 51–56；左腿 CAN-FD0、右腿 CAN-FD1 |
| `robot_joints_tienkung.yaml` | 左右腿逐字段完全相同（min/max_pos ±3.14、max_vel 3.0、max_effort 80.0、enable_default true） |
| `z01_pa_walk.yaml` | kp/kd 左右一致（髋膝 150/5、踝 30/2）；踝默认位姿镜像（±0.238） |

**推论**：既然配置、静态标定都对称，数据里看到的左右不对称**不来自配置**，只能来自①物理/机械个体差异（现场实测）或②RL 策略行为（命令尖峰 / 步态）。**靠改配置消除左右不对称这条路走不通。**

> 附带：当前 `z01_pa_walk.yaml` 的 kd 已从之前误改的 8 **回退到 5**、踝 kp=30（左右对称）。

### 4.7 IMU 姿态：行走时机身基本水平，无持续左倾

- 单位确认为**度**（yaw 范围 ±180）；
- RUN 段 `roll` 中位 **−0.08°**，p1=−3.98°、p99=+3.63°（98% 落在 ±4° 内）；
- PREPARE 静态 roll 中位 −0.79°、pitch +0.72°。

**结论**：机身在行走中保持水平，**重心偏左不是因为机身倾斜**。

### 4.8 步态幅度存在左右差异（091629，RUN 段位置范围）

| 关节 | 范围 | 峰峰值 | mean |
|---|---|---:|---:|
| 左髋pitch | [−0.809,−0.096] | 0.713 | −0.133 |
| 右髋pitch | [−0.790,−0.045] | 0.745 | −0.171 |
| **左膝** | [+0.167,+1.440] | **1.273** | **+0.307** |
| **右膝** | [+0.139,+1.193] | 1.054 | +0.212 |
| 左踝pitch | [+0.025,+0.879] | 0.853 | +0.205 |
| 右踝pitch | [−0.917,−0.003] | 0.913 | −0.079 |

左膝活动范围（峰峰 1.273）与均值屈曲角（+0.307）都大于右膝（1.054 / +0.212）→ 左膝在步态中屈伸更大、更屈曲，是真实的步态不对称线索（踝 pitch 左右镜像属正常并联踝符号约定）。

### 4.9 转向不对称（091221，右转侧偏）

- 右转持续侧偏、左转正常原地转；
- 右髋 roll：命令 −0.064、实际 −0.003、偏置 +0.062、力矩约为左侧 2 倍；
- 启动零位：left_hip_roll −4.94° vs right_hip_roll −8.70°（差 3.76°）、hip_yaw 差 5.32°；
- 机理：原地转需髋 roll 做侧向重心转移，右髋 roll 执行不足导致右转外偏。

> 注：此项与 §4.5 的「右髋 roll 命令尖峰」可能同源（策略在该关节输出异常），需结合现场进一步确认。

## 5. 存疑 / 未决问题

### 5.1 ⚠️「重心持续偏左」存在数据矛盾（核实被中断，待重做）

在核实左腿承重时发现两个互相矛盾的结果：

| 指标 | 数值 | 含义 |
|---|---|---|
| 全 RUN 段左膝 \|tau\| **median** | 14.35（右膝 1.36） | 若成立 → 约 50% 帧左膝力矩 >14 |
| 全 RUN 段左膝 \|tau\|>15Nm **帧占比** | **仅 3.2%**（右腿 1.7%） | 与 median=14.35 **直接冲突** |
| t=100~104s 时序采样 | 左膝 ≈3.4、**右膝 ≈4.3** | 该时段右膝反而更吃力 |

- median=14.35 与「仅 3.2% 帧 >15Nm」在数学上不可能同时成立，**说明其中一处统计有误或承重是强阵发**（大部分时段左膝力矩很低，个别时段剧烈重载拉高整体）；
- 因此「重心一直在左腿」**尚未被稳健证实**，需重做：分时段（如每 240s）统计左右膝 `|tau|` 的 median/mean，定位重载到底发生在哪些时间窗，再结合 IMU roll、步态相位判断是「策略步态偏载」还是「某动作/转向段临时偏载」。

### 5.2 命令尖峰的确切来源未定位
尖峰是 `policy` 输出饱和，还是 50Hz→200Hz 下发插值 bug，尚未在 `robot_rl_manager` 代码层面确认。

### 5.3 左膝电机健康未确认
长期重载 + 过流后，motor_id=44 是否已退化需现场检测。

## 6. 修复建议（按优先级）

1. **命令速率限幅（首选，治本且不碰 RL 增益）**：在命令下发处对关节位置命令做每帧跳变钳制（如 ≤0.05~0.1rad/帧），直接砍掉 0.9rad 级毛刺。**不改 kp/kd、不用重训**，对所有关节生效、左右都受益。
2. **输出力矩限幅**：在 `robot_control` PD 之后加力矩钳制（钳到 `max_effort=80Nm` 内）+ 力矩速率限幅（`|dτ/dt|` 峰达 42000Nm/s），防止过流保护触发。属安全滤波，不破坏策略动力学。
3. **排查命令尖峰来源**：`robot_rl_manager` 的 50Hz policy 输出 → 200Hz 下发插值/丢帧逻辑，或 policy 在特定状态下的饱和输出。
4. **保持训练增益**：髋膝 kd=5、踝按训练值；**切勿用经典 PD 调参直觉去改固定 RL 策略的部署增益**（曾把 kd 5→8 导致全面恶化，见 §4.3 关联）。需改增益必须重训或对 kd 做 domain randomization。
5. **现场检查**：右髋 roll / 左膝的机械装配、摩擦、走线、限位；左膝电机健康。
6. **复测前**：先确认过流可复现性，避免再次触发保护停机。

---

## 7. 重要教训

- **RL 策略部署增益是训练绑定的，不可擅调**：把髋膝 kd 5→8、踝 kp 60→50 后（191350 vs 184341），`L_knee|tau|max` 156→200Nm、大误差帧（|e|>0.4）34→118、`tau>80` 帧 18→55，全面恶化。经典「corr(τ,v)≈0 → 加 kd」直觉对固定 RL 策略不适用，是误判。
- **暴力补偿要看命令端**：`np.diff(q_cmd)` 若 mean 极小而 max 很大（0.5~0.9rad/帧），即 RL 命令毛刺被高 kp 放大，而非硬件跟不上。修命令尖峰用**速率限幅**，不碰 RL 增益。
- **力矩长期超 max_effort 会触发过流停机**：左膝 166Nm（额定 80Nm）直接烧到 motor_error=32 保护。
- **区分嫌疑的标准手法**：静态标定（PREPARE 左右对比）、响应延迟（互相关）、命令尖峰（diff）、承重不对称（RUN 各关节 `|tau|mean`）四把尺子分开量，避免把「受害者关节」误判为「根因」。

## 附录 A：关键脚本骨架

```python
import numpy as np, csv
from pathlib import Path
from scipy.signal import butter, filtfilt

LOG = Path('logs/20261015_091629/recorder')

def load(p, cols):
    d = []
    with open(p) as f:
        r = csv.DictReader(f)
        for row in r:
            d.append([float(row[c]) if row.get(c, '') else np.nan for c in cols])
    return np.array(d, dtype=np.float64)

C = load(LOG/'joint_commands.csv', ['msg_stamp_ms', 'type', 'leg_l_4_pos'])
cs, ct = C[:,0].astype(np.int64), C[:,1]
S = load(LOG/'joint_states.csv',
         ['msg_stamp_ms', 'leg_l_4_pos', 'leg_l_4_vel', 'leg_l_4_tor', 'imu_euler_roll'])
st = S[:,0].astype(np.int64)

# 时间对齐 + RUN 掩码
idx = np.clip(np.searchsorted(cs, st), 1, len(cs)-1)
tl = np.abs(cs[idx-1]-st) <= np.abs(cs[idx]-st)
match = np.where(tl, idx-1, idx)
run = (np.abs(cs[match]-st) <= 15) & (ct[match] == 4)

# kp/kd 反算
e = C[match, 2] - S[:, 1]
A = np.column_stack([np.ones(run.sum()), e[run], -S[run, 2]])
sol, *_ = np.linalg.lstsq(A, S[run, 3], rcond=None)   # sol[1]=kp, sol[2]=kd

# 命令尖峰
d = np.abs(np.diff(C[run, 2]))
print('cmd跳 mean/max:', d.mean(), d.max())
```

## 附录 C：术语

- **暴力补偿**：关节力矩短时爆发（远超正常行走水平）以追赶命令的现象；
