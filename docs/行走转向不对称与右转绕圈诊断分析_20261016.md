# 行走转向不对称与右转绕圈诊断分析

> 分析对象：`z01_pa_walk` RL 行走策略在天工（tienkung）双足平台上的实测日志
> 分析时间：2026-10-16
> 分析方法：基于 `recorder/` 下 `joint_commands.csv` / `joint_states.csv`（200Hz）的离线数值分析（方法论沿用《腿部电机暴力补偿与过流诊断分析_20261015.md》§3）
> 现象：行走时左右转状态不一致——**左转能原地转，右转持续右偏绕圈**
> 关键背景：**同一策略在别的机器人上执行正常；本机更换电机后出现此现象**
> 结论状态：闭环因果链已由转向段起始时序、负载相关偏置演化、IMU 姿态三组证据交叉验证

---

## 1. 背景与目标

用户报告机器人行走时左右转不对称：左转正常原地转，右转持续向外偏、绕圈。关键约束：

1. 同一 RL 策略（`z01_pa_walk`）在**其他机器人上无此现象**；
2. 本机**更换电机后**才出现；
3. 所有可用日志均为换电机之后录制，无换电机前的基线日志。

分析目标：

1. 用 IMU 数据 + 电机指令 + 电机执行情况三层数据定位右转右偏的根因；
2. 回答核心因果问题：**是策略下发的指令本身不对称（开环问题），还是执行不好通过闭环观测逼策略改变输出（执行问题）**；
3. 给出可执行的排查建议。

## 3. 分析方法

### 3.1 数据对齐与分段
- 命令帧-状态帧最近邻对齐（`searchsorted`，时差 ≤15ms，仅保留 type=4 RUN 帧）；
- IMU `gz`（deg/s→rad/s）经 Butterworth 2Hz 低通，以 ±0.3 rad/s 阈值划分左转/右转/直行段；
- `imu_euler_roll/pitch/yaw` 单位为度。

### 3.2 因果区分三判据
| 判据 | 方法 | 含义 |
|---|---|---|
| A 跟随精度 | 转向段 cmd vs act 误差 | 命令能否被执行（硬件能力） |
| B 跨日志对比 | 零位对称日志 vs 零位偏日志的不对称度 | 零位/标定是否为主因 |
| C 时序演化 | 转向段起始 0.6s 内 cmd/act/IMU 逐 100ms 时序 | 开环不对称则起步即偏；闭环补偿则先有执行/姿态异常、后有命令改变 |

判据 C 是决定性判据：**开环问题在转向一开始就表现为不对称命令；闭环补偿则必然先出现执行/状态异常，命令随后才被改变**。

---

## 4. 关键分析结论

### 4.1 指令层：策略起步时对称发力（关键反证）

右转段（gz 拉至 −0.9 rad/s）起始 0.5s 逐 100ms 时序：

| dt | gz(rad/s) | L_hy_cmd | R_hy_cmd | IMU roll |
|---:|---:|---:|---:|---:|
| +0.1s | −0.45 | +0.052 | **−0.103** | −1.0° |
| +0.2s | −0.63 | +0.121 | **−0.193** | −1.3° |
| +0.3s | −0.79 | +0.175 | **−0.187** | −0.5° |
| +0.4s | −0.90 | +0.154 | **+0.021** ← 右腿被撤回 | +1.2° |
| +0.5s | −0.96 | +0.037 | +0.095 | +2.8° |

- 策略在右转起步 0.2~0.3s **双腿对称蹬**（R_hy_cmd 一度达 −0.19，与左转时同等力度）；
- 同时刻 IMU roll 从 −1.3° 恶化到 +2.8°（重心侧移失败）；
- dt=+0.4s 起策略才把右腿命令撤回 ≈0，退化为「只蹬左腿」的稳态不对称（左转段 R_hy_cmd=−0.094 vs 右转段 R_hy_cmd=+0.009）。

> 若为策略开环不对称，起步时不应出现 −0.19 的对称发力。**策略"会"用右腿，是观测到身体状态不对才放弃**——与「别的机器人上正常」完全吻合：策略没变，是本机执行层把它逼进失败分支。

### 4.2 执行层：髋 roll 双侧欠执行，右转时左髋 roll 被打爆

**静息/直行即欠执行（换电机的指纹）：**

| 段 | L_hr cmd→act | R_hr cmd→act | 执行率 |
|---|---|---|---:|
| 直行 | +0.055 → **+0.013** | −0.061 → **+0.007** | **20~30%** |
| 左转 | +0.100 → +0.047 | −0.112 → −0.032 | ~35% |
| 右转 | +0.096 → +0.029 | −0.117 → −0.040 | ~30% |

双腿髋 roll 只能执行命令的三成；右髋 roll 慢性最差（站立偏置 −0.075rad、持续 ~15Nm 保持力矩，左 ~10Nm）。

**负载相关 = 硬件问题，非零点漂移**（30s 窗偏置演化）：

| 时段 | 工况 | L_hr 偏置 | R_hr 偏置 |
|---|---|---:|---:|
| t=30~90s | 转弯多 | +0.05~+0.07 | −0.07~−0.09 |
| t=120~330s | 久站 | +0.063 | −0.065 |
| t=480~590s | **休息/卸载** | **−0.014（部分恢复）** | **−0.035（部分恢复）** |
| t=630~660s | 再转弯 | +0.05（再恶化） | −0.08（再恶化） |

卸载后偏置部分恢复 → 排除编码器零点漂移，判定为**带载执行能力不足**（摩擦/背隙/扭矩不足），负重时被压回。

**右转时左髋 roll 力矩打爆至 144Nm（超 max_effort=80）：**

```
t=650.4s: L_hr cmd=+0.418  act=-0.032  tor=144Nm  roll=+2.5°
t=697.5s: L_hr cmd=+0.512  act=-0.042  tor=102Nm  roll=+3.3°
t=388.8s: L_hr cmd=+0.451  act=+0.010  tor=95Nm   roll=+1.9°
```

- 正常转弯 cmd≈+0.10，策略加码到 **+0.45~0.51（4~5 倍）**——典型闭环补偿：观测到重心没移过去，不断加大髋 roll 命令；
- `corr(|tor|,|e|)=0.943`：控制器按误差拼命出力，关节纹丝不动（act 卡 ~0）；
- 温度左右对称（34~44°C）→ 排除过热降扭；
- 左转段左髋 roll 力矩峰仅 24~76Nm，从不打爆。

**对照**：hip_yaw 本身跟随良好（err≈0.03rad）——左转时 R_hy_cmd=−0.094 被精准执行到 act=−0.107，证明右腿髋 yaw 电机完全有能力；右转时它「没被命令动」而非「动不了」。

### 4.3 IMU 层：右转时身体持续侧倾

| 段 | roll mean | roll p95 | roll std |
|---|---:|---:|---:|
| 左转 | −0.53° | +2.70° | 2.40° |
| **右转** | **+1.92°** | **+5.17°** | 2.16° |
| 直行 | +0.16° | +0.31° | 0.44° |

右转机身 roll 均值是左转 3.6 倍且持续偏向一侧 → **右转时重心侧移始终未完成、机身处于倾斜状态**，这正是策略观测到并被迫响应的状态。

### 4.4 完整因果链

```
换电机后 → 髋roll带载执行不足（双侧，右侧慢性更差）
                │
   右转需重心侧移 → 左髋roll被压死（act卡0）→ 策略闭环加码 cmd→0.45
                │                              → 力矩打爆144Nm仍移不动
                ▼
   IMU roll 持续 +2~5°（身体侧倾，重心没移过去）
                ▼
   策略观测到姿态不对 → 右腿无法卸载 → 撤回右腿髋yaw（R_hy_cmd≈0）
                ▼
   只剩左腿单腿推 → 推力不通过重心 → 边转边平移 → 右转绕圈/右偏
```

- **为什么左转正常**：左转的重心转移方向与静息偏置方向一致（站立时本就略偏右），需求更小，策略无需加码，双腿 yaw 均正常参与 → 原地转；
- **为什么别的机器人正常**：同一策略下，那些机器髋 roll 能完成重心转移，闭环永不进入「侧倾→撤右腿」失败分支。

### 4.5 与 1015 文档结论的关系

- 本文结论**修正并统一**了《腿部电机暴力补偿与过流诊断分析_20261015.md》§4.9（091221 右转侧偏：右髋 roll 执行不足）与早期「策略 hip_yaw 开环不对称」的判断：
  - **髋 yaw 命令不对称是稳态表象（果）**，其跟随精度本身良好；
  - **髋 roll 带载执行不足是因**，与 091221 的诊断（右髋 roll 执行不足、力矩 2 倍于左侧、零位偏）一脉相承；
- 1015 文档 §4.9 中「右髋 roll 命令 −0.064、实际 −0.003」与本日志「cmd −0.061→act +0.007」模式一致，跨日志复现。

## 5. 存疑 / 未决问题

1. **更换的具体电机未确认**：数据最强指向髋 roll（motor_id 42/52）——右髋 roll 慢性偏置（全天候）+ 左髋 roll 负重饱和（144Nm）。需现场确认换的是哪个/哪侧电机，以缩小排查范围。
2. **执行不足的物理机理未定**：摩擦、背隙、装配同轴度、kt 不匹配（新电机实际力矩常数与配置 `kt: 3.5` 不符）均可能，需现场鉴别。
3. **右髋 yaw 零位偏 −6.5°~−10°**：本次开机自检零位明显偏移，与转向问题的耦合度未定量，建议复标后复测。
4. **无换电机前基线日志**：无法直接对比更换前后的执行率变化，结论依赖「同策略跨机体正常」这一外部证据。

---

## 6. 排查建议（按优先级，只读/不动硬件优先）

1. **断电手掰对比**：左右髋 roll 各掰一遍全行程，感受阻力/卡点是否对称（新电机背隙小、装配同轴度差都会表现为带载卡死）；
2. **核对 kt**：新电机实际力矩常数与 `hw_tienkung.yaml` 中 `kt: 3.5` 是否一致——若新电机 kt 更小，同电流出力不足，正好解释「命令到位、力矩记录在涨、关节不动」；
3. **检查相线/相序与减速器装配**（换电机后最常见问题）；
4. **复标右髋 yaw 零位**（本次开机偏 −6.5°；标零前先用 `scripts/motor.sh` 的 query_status 只读确认通信正常，遵循先使能握手再发标零命令的规程）；
5. **修复后复测**：录制新日志，核对「髋 roll 执行率恢复 >70%、右转段 IMU roll 均值回到 ±1° 内、R_hy_cmd 恢复对称发力」三项指标。

## 7. 禁忌（避免误诊误修）

- **不要改策略、不要给髋 yaw 加不对称补偿**——它是受害者不是肇事者，且违反关节映射/策略语义的 Hard Invariants；
- **不要单独提高髋 roll kp**——RL 部署增益与训练绑定（见 1015 文档 §7 教训），且此处执行端 144Nm 都推不动，不是增益问题；
- **不要凭稳态数据下「策略开环不对称」的结论**——必须看转向段起始时序（判据 C），稳态不对称命令可能是闭环补偿的结果。
